## Buyer journey and state

- Start with no saved/compared cars. Home finder: Used, sedan, budget 40000; verify `view=all`, the two matching cars, and price ordering.
- Save at least four valid cars; confirm saving never changes comparison. Open saved drawer, remove and undo with focus retained.
- Compare City sedan, Sport sedan and Family SUV. Reject a fourth without replacing an existing car. Check empty and one-car prompts, differences-only, missing values and all three columns.
- Inspect City sedan; verify $22,500, 42,000 km and sample history. Follow specification, price and sample-review tabs; preserve selected ID and safe return filters.
- Open a shared comparison different from device selection. Reading must not overwrite device state. An explicit edit updates both URL and stored selection. Check `cars=`, invalid/duplicate/excess IDs, back/forward, remove/undo order.
- Validate corrupt/unavailable storage through pure regression tests and user-visible notices. The selected browser skill prohibits browser-storage inspection; do not read or mutate storage through browser tools.

## Inventory and URLs

- Exercise all condition/body/budget/view/sort choices against the canonical catalogue. Price sorting puts unknown prices last; numeric budgets exclude them with an explanation on upcoming views.
- Remove individual chips and clear a zero-result state. Verify browser back/forward without an extra history push.
- At mobile width, change filter drafts and cancel/Escape without affecting results. Reopen, apply, and verify one committed state plus restored focus.
- Open every existing HTML route directly. Check bare representative fixtures, explicit invalid/blank ID and valid ID on a mismatched detail filename. Upcoming records never offer enquiry/reservation.
- Check malformed filter text is not rendered as markup; all visible links resolve and no `href="#"` placeholders remain.

## Forms and privacy

- Enquiry, seller, review and valuation: empty preview → accessible errors → fictional sample → review → edit → finish with exact “Demo preview only — nothing was sent.”
- Reset, close, Escape, reload and back/forward must clear fields, error state and review content. Valuation never generates an estimate/offer.
- Verify no form navigation or receiver call while typing/previewing/finishing. Inspect supported browser diagnostics; additionally audit runtime modules and CSP for network/storage boundaries. Record any unsupported storage/network inspection, not a false pass.
- No contact/free text belongs in URL or app storage. Static HTML contains empty personal/free-text values, disabled fieldsets and no submit controls.

## Accessibility, responsive and visual QA

- Keyboard: skip link; all nav; mobile menu; dialogs with focus containment and Escape/return; error summary; comparison scroller; status announcements.
- Check all fourteen routes at 1440/768/390/320 widths and 200% zoom where supported. No page-wide overflow; mobile comparison scrolls internally with persistent attributes. Controls remain approximately 44px and body/form text at least 16px.
- Confirm local Manrope and Barlow Condensed render, all styles/images load and browser console has no unexplained errors.
- No-JS representative content/navigation remain readable and forms cannot submit; reduced-motion content is immediate. If browser setting emulation is unsupported, label static/runtime evidence separately.
- Compare matching source reference and rendered screenshot in the same inspection input for home, inventory, vehicle, comparison and forms, desktop/mobile and key states. Record scale/state limitations and all fix/recheck iterations in project-root `design-qa.md`.
